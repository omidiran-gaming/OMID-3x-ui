# 3X-UI روی Lucity با Reverse Proxy برای WebSocket

این نسخه از سورس اصلی 3X-UI ساخته شده و Nginx را در همان کانتینر اضافه می‌کند. این تنظیم، ترافیک HTTPS ورودی Lucity را روی پورت داخلی 2053 می‌گیرد و آن را بر اساس مسیر به پنل، سرویس ساب یا یک اینباند WebSocket می‌فرستد.

## دیپلوی

1. محتوای این ریپازیتوری را به GitHub خودت Push کن.
2. در Lucity گزینه دیپلوی از GitHub را انتخاب کن و Build با Dockerfile ریشه پروژه را استفاده کن.
3. در Networking پورت اپلیکیشن را روی `2053` قرار بده؛ Nginx در این نسخه روی همین پورت گوش می‌دهد.
4. حتماً Volume/Storage پایدار را روی `/etc/x-ui` متصل کن تا دیتابیس و تنظیمات پنل بعد از redeploy باقی بمانند.
5. برای این نسخه متغیر `XUI_PORT` را تغییر نده: پنل اصلی داخل کانتینر روی `8080` گوش می‌دهد و Nginx پورت `2053` را اشغال می‌کند.

## تنظیم اینباند VLESS + WS

در سنایی یک اینباند بساز با این مقادیر:

- Protocol: `VLESS`
- Port: `8081`
- Network/Transport: `WS`
- Path: `/ws`
- TLS داخل Xray: خاموش/None؛ TLS عمومی را Lucity خاتمه می‌دهد.

در لینک کلاینت، دامنه عمومی و HTTPS/پورت 443 را استفاده کن، با `type=ws`, `security=tls`, `host=<دامنه>` و `path=%2Fws`. این کار فقط وقتی جواب می‌دهد که Lucity درخواست‌های WebSocket را عبور دهد و دامنه به سرویس این اپلیکیشن اشاره کند.

## تنظیم ساب‌لینک

در Settings → Subscription، مسیرها را با Nginx هماهنگ کن:

- Subscription path: `/sub/`
- JSON path: `/json/`
- Clash path: `/clash/` (اگر فعال است)
- Listen port: `2096`
- TLS/Certificate در سرویس ساب را خالی بگذار؛ Nginx به سرویس داخلی HTTP وصل می‌شود.
- Reverse Proxy URI: `https://YOUR-DOMAIN/sub/`
- اگر JSON یا Clash را فعال می‌کنی، URI آن‌ها را هم جداگانه به‌ترتیب `https://YOUR-DOMAIN/json/` و `https://YOUR-DOMAIN/clash/` تنظیم کن.

جایگزین `YOUR-DOMAIN` را با دامنه‌ای که در Lucity متصل کرده‌ای عوض کن. چون 3X-UI ممکن است در اولین راه‌اندازی برای مسیر ساب پیشوند تصادفی بسازد، مسیرها را در تنظیمات کنترل کن و دقیقاً با مقادیر بالا هماهنگشان کن.

## نکات مهم

- `2053` پورت داخلی اپلیکیشن Lucity/Nginx است؛ `8080` پورت خصوصی وب پنل؛ `8081` اینباند WS داخل کانتینر؛ `2096` سرویس ساب داخلی. این پورت‌های خصوصی را به عنوان پورت عمومی جداگانه فرض نکن.
- این پیکربندی فقط مسیرهای `/ws`, `/sub/`, `/json/`, `/clash/`, `/mihomo/` و `/clash-legacy/` را مسیریابی می‌کند. برای مسیرهای سفارشی باید `nginx/default.conf` هم تغییر کند.
- این روش برای VLESS + WebSocket است؛ پورت‌های TCP خام، REALITY، UDP و سایر transportها با این Reverse Proxy به‌صورت خودکار کار نمی‌کنند. به قابلیت‌های شبکه Lucity نیز وابسته است.
- اگر از قبل `/etc/x-ui` را به Volume متصل نکرده‌ای، قبل از جایگزین‌کردن ایمیج حتماً دیتابیس/تنظیمات را پشتیبان بگیر.
